# Клинична лаборатория – Интерактивно обучение

Образователен уебсайт за студент по медицина: десет урока с интерактивни визуализации за аналитичните методи в клиничната лаборатория, калибрацията и вътрешнолабораторния качествен контрол. Целият интерфейс е на български.

Сайтът е **само фронтенд**: няма сървър, база данни, API, автентикация, потребителско съдържание, административен панел или чатбот. След изграждането е набор от статични файлове, които работят и без интернет.

> Материалът е образователен. Той не е предназначен за клинична диагностика или за решения за конкретен пациент.

## Стартиране

Изисква Node.js 20.19 или по-нов.

```bash
npm install        # зависимости
npm run dev        # сървър за разработка (http://localhost:5173)
npm run build      # производствено изграждане в dist/
npm run preview    # локален преглед на изградения сайт
npm run typecheck  # проверка на типовете (tsc)
```

## Статично публикуване

`npm run build` създава папката `dist/`. Тя е напълно статична:

- `base` във `vite.config.ts` е `./`, затова сайтът работи от всяка папка или поддомейн;
- навигацията е с hash-маршрути (`#/metodi/hplc`), затова **не е нужна** конфигурация на сървъра за пренасочване;
- няма външни шрифтове, изображения, скриптове или заявки – всички схеми са локални SVG/CSS.

Копирайте съдържанието на `dist/` на всеки статичен хостинг (GitHub Pages, Netlify, Cloudflare Pages, Nginx, Apache, обикновена папка в университетска мрежа).

### Единичен файл за работа без сървър

```bash
npm run build:offline
```

Създава `dist-offline/index.html` – един файл (≈1,1 MB) с вграден JavaScript и CSS. Отваря се с двоен клик (`file://`) и работи без интернет, например от USB устройство.

## Как се променя съдържанието

Съдържанието е **фиксирано в изходния код** и в интерфейса няма начин да се добавя, редактира или трие. Нови теми и промени в уроците се правят само от разработчика – чрез изрична заявка към Claude Code или чрез директна редакция на файловете:

1. Текстът на урока е в `src/data/content/<урок>.ts` като типизирани блокове (`p`, `h3`, `ul`, `ol`, `callout`, `qa`, `formula`, `table`). В текст се поддържат само `**удебелено**` и `{{термин|обяснение}}` (подсказка).
2. Каталогът е в `src/data/topics.ts`, източниците – в `src/data/references.ts`.
3. След промяна пуснете `npm run verify:content` – проверява броя и номерацията на въпросите, наличието на източници и терминология.

Принципи за научна коректност, заложени в кода:

- Не се измислят реакции, състави на реактиви, дължини на вълните или параметри на уреди.
- Подробности, зависими от производителя, са означени („вж. листовката на реактива/апарата“); неизвестното е означено като „изисква проверка“.
- Всеки урок завършва със списък с източници; цитират се само публикации, чието съществуване е известно.
- Числата във визуализациите (мътност, абсорбция, времена на задържане, контролни стойности и др.) са образователни и са обозначени като илюстративни.

## Достъпност

Семантичен HTML, „Към съдържанието“ като първи фокусируем елемент, управление с клавиатура (включително Ctrl+K за търсене и Esc за затваряне), `aria-live` за обясненията на етапите, подсказки с `title` и `role="tooltip"`, светла тема по подразбиране с избираема тъмна (запазва се в браузъра) и пълна поддръжка на „намалено движение“ (`prefers-reduced-motion`).

## Проверки, извършени при разработката

Скриптовете в `scripts/` са помощни и не влизат в сайта:

| Скрипт | Какво проверява |
|--------|-----------------|
| `smoke.mjs` | всеки маршрут (десктоп и мобилен) – без грешки в конзолата, без хоризонтално превъртане, без външни заявки |
| `interact.mjs` | управлява визуализациите (етапи, плъзгачи, избор, пускане/пауза) и записва снимки |
| `ui-checks.mjs` | тъмна тема, търсене, мобилно меню, ред на десетте раздела, протекли маркери в текста |
| `overflow-check.mjs` | елементи, излизащи извън екрана при 390, 360 и 320 px |
| `verify-content.mjs` | въпроси 10/10/12/12/12/12/12/15/11/13, източници, терминология, липса на „TODO“ |

Скриптовете за браузър използват Playwright и Chrome/Chromium.

## Бележки за изграждането

Стекът е React, TypeScript, Vite и Tailwind CSS. Вместо Lucide React, Recharts и Framer Motion са използвани **собствени** компоненти: набор от SVG икони, ръчно изчертани SVG графики и CSS анимации с уважение към „намалено движение“. Това намалява зависимостите (само `react` и `react-dom` в производствения пакет) и гарантира, че диаграмите са напълно локални.

Средата, в която е разработен проектът, нямаше достъп до npm. Затова:

- `npm run build` (Vite) и `npm run typecheck` с реалните `@types/react` **не са изпълнявани** тук; проектът е проверен със същите esbuild и Tailwind компилатор (`npm run build:offline`) и в реален браузър, а типовете – срещу опростена декларация на React. При първия `npm install` е възможно `tsc` да покаже дребни несъответствия в типовете, които не променят поведението.
- Ако `npm run build` даде грешка, изпратете съобщението и ще бъде поправено.
